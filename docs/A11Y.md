# Accessibility

The target is WCAG 2.2 AA (see `docs/PLAN.md`). This page lists what the automated tests check, what a screen reader is given, and what has **not** been tested. The tests run with `make e2e`.

## What is not tested

No person has used Lesson Coach with a real screen reader: not NVDA, JAWS, VoiceOver or TalkBack. Everything below was checked by tests reading Chromium's accessibility tree, which is what a screen reader receives. It was not checked by listening to one. In particular:

- **How voices read the spoken math.** Each expression gets a spoken label in the active language, such as "one half plus one third". The tests check that label in all 19 languages, not how a voice pronounces it. Every language but English is machine-translated and unreviewed, so a native speaker has not confirmed that the spoken math reads naturally.
- **Other languages with a screen reader.** No one has listened to Arabic, Persian, Urdu, Hindi, Bengali or Chinese pages with a screen reader, so voice switching on the `lang` marks is untested.
- **Typed math.** MathLive (the typed math field) has its own speech and keyboard handling. The tests type into it and check its label, but not what it says while you edit.
- **The drawing board.** It is checked through its text alternatives only: Type is always one tab away, and the confirm screen lists the lines in text. No one has drawn with a switch device or screen magnifier.
- **Browsers.** Only Chromium was tested; Firefox and Safari were not.

A human pass with NVDA on Windows and VoiceOver on macOS and iOS is still to do. The keyboard paths and tree excerpts below are a good script for it.

## Automated checks

| Check | Where | What |
|---|---|---|
| axe-core, WCAG 2.0–2.2 A and AA (includes 2.5.8 target size) | `e2e/a11y.spec.ts` | Every page in every state (below), at 5 layouts: desktop 1280 px, tablet 820 px, phone (Pixel 7, touch), 320 px wide, 200% zoom |
| Reflow: no sideways page scroll (1.4.10) | same | Same states and layouts |
| Nothing clipped | same | No element that hides its overflow holds more text than it shows |
| Keyboard only (2.1.1) | `e2e/keyboard.spec.ts` | Each page's main task with Tab, Shift+Tab, Enter, Space, arrow keys and Esc, at desktop and 200% zoom |
| Visible focus (2.4.7, 1.4.11), focus not hidden (2.4.11) | same | At every focus stop on those paths: an outline or ring at least 2 px wide with 3:1 contrast against white, gone again once focus moves on, and the element is not under the sticky header |
| Reduced motion (2.3.3) | `e2e/motion.spec.ts`, `e2e/demo.spec.ts` | Under `prefers-reduced-motion: reduce`, no CSS animation runs and nothing loops on home, a chosen step with its picture, and a circled mistake; without it the hero float, the line marker and the drawn circle do run. The write-on is checked on `/demo/math` |
| Print | `e2e/print.spec.ts` | Topic prints only its title and the timed outline; Practice and a Mistake result print without the header, with nothing clipped |
| Accessibility tree | `e2e/aria.spec.ts` | Landmarks, a worked example (English and Arabic), the hint ladder, a mistake result |
| Other languages | `e2e/rtl.spec.ts` | Every page (home, a step's picture, practice with a checked line and a hint, a mistake diagnosed and unclear, not found) with axe, reflow and clipping: Arabic at desktop, 320 px and 200% zoom; Simplified Chinese at desktop and 320 px; Hindi at desktop. Real translated packs; only the model calls are mocked |
| RTL | `e2e/rtl.spec.ts`, `e2e/pages.spec.ts`, `e2e/shell.spec.ts`, `e2e/input.spec.ts`, `e2e/demo.spec.ts` | Arabic, Persian and Urdu pages are right to left with every `role="math"` left to right; an English pack is marked `lang="en"`; Arabic prints right to left with nothing cut off |
| Spoken math per language | `e2e/rtl.spec.ts` | In all 19 languages, the label of `2x + 6 = 10` equals the text built from that locale's `math.speech` templates, so it is never the English reading |
| Language switch | `e2e/rtl.spec.ts`, `e2e/keyboard.spec.ts` | By keyboard on the picker: `lang` and `dir` on `<html>` follow, focus stays on the picker, and the heading and spoken math change language |
| Fonts per script | `e2e/rtl.spec.ts` | For each script (Latin, Cyrillic, Greek, Arabic, Devanagari, Bengali, Simplified Chinese), Chromium's own report of the fonts used shows the script's web font for body text, navigation and handwriting, and no system font, so there is no tofu |
| Real content, no mocks | `e2e/real.spec.ts` | The production build with the real packs, axe on each topic |

The 200% zoom layout is a 640×400 CSS viewport at twice the pixel density: that is what a 1280×800 window shows at 200%, and CSS layout depends only on CSS pixels.

### States in the matrix

- **Home:** loading, loaded, topics failed.
- **Topic:**
  - loading, loaded;
  - a step explained in each of Why?, Another way and Picture (in the bottom sheet on a phone);
  - the last worked example with a question open;
  - served in English under the Arabic UI;
  - failed to load, unknown topic.
- **Practice:**
  - a problem, the last problem;
  - checked with nothing written;
  - every line follows, a line that doesn't follow, the check failed;
  - one hint open, the answer shown;
  - Practice with no topic that has problems.
- **Mistake:**
  - empty, missing problem and answer, the Write and Photo tabs;
  - each result: diagnosed, correct, not simplified, slip, unclear, out of scope;
  - rate limited;
  - every abstain reason (9).
- **Not found.**

Results that need the language model come from the route-mocked API (`e2e/api.ts`), so the tests never call Azure.

### Keyboard paths

- **Home to a lesson:**
  1. Tab to a topic card, then Enter.
  2. Tab to a worked-example line, then Enter. On a phone or at 200% zoom, the explanation opens in a sheet.
  3. Use ←/→ to switch between Why?, Another way and Picture. Esc closes the sheet.
  4. Shift+Tab to Next worked example, then Enter.
  5. Tab to a question, then Enter to open it.
  6. Tab to "Try these problems yourself first", then Enter.
- **Practice:**
  1. Tab to the input tabs and press ← to choose Type.
  2. Tab into the field and type the working.
  3. Tab to Check my working, then Enter.
  4. Tab to Show next hint and press Enter, four times.
  5. Shift+Tab to Start over, then Enter. Focus moves to Show next hint.
  6. Shift+Tab to Next problem, then Enter.
- **Mistake:**
  1. Tab to a topic and press Space.
  2. Tab into the problem and type it.
  3. Tab into the answer and type it.
  4. Tab to Explain this, then Enter.
  5. Tab to Try another answer, then Enter. Focus moves back to the answer field.
- **Language:** Tab to the picker, then ↓/↑. The page switches language and direction, and focus stays on the picker.
- **Phone sheet:** Enter on a line opens the sheet. Tab to Next step and press Enter. Esc closes the sheet, and focus returns to the line now selected.

## What a screen reader is given

These are excerpts of Chromium's accessibility tree, the same ones `e2e/aria.spec.ts` checks.

**The page.** It has a skip link, then the banner with the main navigation and the language picker, then main with one h1, then the footer. Each section of a topic is a labelled region with its own h2.

```yaml
- link "Skip to main content"
- banner:
  - link "Lesson Coach"
  - navigation "Main": [Topics, A student wrote this, Practice]
  - combobox "Language"
- main:
  - heading "Solving linear equations" [level=1]
  - navigation "On this page"
  - region "The idea" … region "Lesson outline"
- contentinfo
```

**A worked example.** Each step is a toggle button. Its name is the spoken math followed by the move that comes next, in the active language:

```yaml
- list "Worked example 1":
  - button "3 x plus 5 equals 20; subtract 5 from both sides" [pressed]
  - button "3 x equals 15; divide both sides by 3"
  - button "x equals 5"
- list "مثال محلول 1":
  - button "3 x زائد 5 يساوي 20؛ اطرح 5 من الطرفين" [pressed]
  - button "3 x يساوي 15؛ اقسم الطرفين على 3"
  - button "x يساوي 5"
```

**Math in text.** Inline math is `role="math"` with a spoken label, for example `math "8 x equals 56"`. A circled line also reads its margin note: "equals the fraction with numerator 1 plus 1 and denominator 2 plus 3, end of fraction; marked: added the bottoms too".

**Hints.** An opened hint is read in full. A closed one says "(not opened)". When a hint opens, focus moves to it. After Start over, focus moves to Show next hint.

**Results.** Results are announced through a polite live region named "Result". Errors use `role="alert"`, and a rate limit says how long to wait.

## Fixed in T11

- **A focused element could be hidden under the sticky header at 200% zoom (2.4.11).** Shift+Tab to Next problem, or to the first worked-example line, scrolled it in under the header. The page now keeps `scroll-padding-top` at the header's live height, so anything focused or scrolled to stops below it.

- **Low-contrast tab on MathLive's on-screen keyboard (1.4.3).** On touch devices the selected keyboard tab was MathLive's blue `#0c75d8` on a grey `#cacfd7`, under 4.5:1. MathLive reads that colour from CSS variables, which are now navy (about 9:1), and pale blue in OS dark mode, where MathLive draws a dark keyboard (about 15:1). `e2e/input.spec.ts` checks the tab in both schemes on a touch device.

- **Faint focus rings on buttons, tabs, accordions and math fields (1.4.11).** The shadcn controls drew their focus as a ring of link blue at 50 % alpha (about 2:1 on white), and the math fields and transcription inputs as a pale blue ring (about 1.2:1). All now draw a navy ring (about 14:1). On a navy button a navy ring would merge into the fill, so buttons keep a 2 px white gap between the two. The keyboard test checks the ring's width and its contrast with the page and with the element's own fill, unless a gap separates them.

## Phase 2 (languages)

Phase 2 ran after the 19 languages shipped (T9). It found no new accessibility bug: every state passed axe, reflow and clipping in Arabic, Chinese and Hindi, and every script draws with its own web font. The font check was shown to work by removing the Arabic font loader, after which Chromium reported the text drawn with DejaVu Sans, a system font.

## Fixed after T11

- **The header covered a third of a phone screen.** On a 390 px phone the sticky header wrapped to 246 px (294 px at 320 px, 171 px at 200% zoom, 125 px of a 390 px landscape screen). It now sticks only in a window at least 768 px wide and 600 px tall; elsewhere it scrolls away with the page, so the privacy note and language picker are still the first things on every page. `--header-h` is 0 when it doesn't stick, so the scroll padding follows. `e2e/a11y.spec.ts` checks what the header covers once scrolled at every layout and in landscape.

## Known and left as is

- **Repeated names.** "What they wrote" is read up to three times: once each for the figure caption, the scroll region and the list. It is verbose but correct. The fix would be dropping the list label inside a captioned figure, and it can wait for a human screen-reader pass.
- **"Refresh first:".** The heading ends with a colon. That is copy in the locale files, which are owned by content.
- **Next problem comes before the hints in Practice.** The Previous/Next links sit under the problem, and the hints panel sits beside it, so Tab reaches Next problem before the hints. This matches the visual reading order.
